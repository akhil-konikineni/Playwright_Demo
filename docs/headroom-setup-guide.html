Headroom + Claude Code
Setup & Troubleshooting

A complete guide to installing and running Headroom as a token-optimization proxy for Claude Code on Windows — including every error encountered and how to fix it.

headroom v0.26.0 Windows 11 Claude Code CLI Python + Node.js Port 8787
§ 01

Overview & Architecture

Headroom is a local proxy server that sits between Claude Code and Anthropic's API. It compresses conversation context before each request, reducing token consumption by 50–90% without changing how Claude Code behaves from your perspective.

Understanding this architecture is key — the most common setup mistake is skipping the proxy startup step. Claude Code must route through Headroom, not talk to Anthropic directly.

You write
Claude Code
↓ ANTHROPIC_BASE_URL=http://localhost:8787
Token optimizer
headroom proxy
↓ Compressed request (50–90% fewer tokens)
Processes
Anthropic API
Two separate installs

Headroom has two components: a Python CLI tool (the actual proxy server) and an npm package (SDK for use inside your Node.js/Playwright project code). Both are installed separately and serve different purposes.

§ 02

Prerequisites

Confirm these are in place before starting. Missing any of these caused real errors during our setup.

  • [✓] Python 3.9+ installed and in PATH — the headroom CLI is a Python package
  • [✓] pip available — run pip --version to confirm
  • [✓] Node.js 18+ and npm — needed for the headroom-ai npm package
  • [✓] Claude Code CLI installed — run claude --version to confirm
  • [✓] Port 8787 free — this is Headroom's default port. Check with: netstat -ano | findstr :8787
Windows PATH note

After pip install headroom-ai, the headroom command is placed in %APPDATA%\Python\Scripts or the Python installation Scripts folder. If PowerShell says "command not found", add that folder to your PATH. On this machine it installed to C:\Users\akhileswar.konikinen\AppData\Local\Programs\Python\Python312\Scripts\.

§ 03

Installation Steps

Complete all four steps in order. Each step is independent but all are required for the full integration.

01
Install the Headroom Python CLI
This installs the proxy server — the core component that intercepts and compresses requests. It provides the headroom terminal command.
powershell Run in any terminal 
pip install headroom-ai

# Verify it installed correctly
headroom --version
# Expected: headroom, version 0.26.0

# Confirm the binary path
where headroom
# Should print a path ending in \Scripts\headroom.exe
If "headroom" is not recognized

pip installed the binary but it's not in your PATH. Find it: pip show headroom-ai — look at "Location", then navigate up to the Scripts folder in the same Python installation. Add that Scripts folder to your System PATH in Windows Environment Variables.

02
Install the npm Package (for your project)
This adds headroom SDK support to your Node.js/Playwright project — useful for programmatic compression in test scripts or utilities. Run this from your project root.
powershell From C:\Playwright\Playwright_MCP 
npm install headroom-ai

# Confirm it's in package.json
# "dependencies": { "headroom-ai": "^0.22.4" }
npm vs pip — different packages, same name

The npm package (headroom-ai) is the JavaScript SDK for using compression inside your code. The pip package (headroom-ai) is the actual proxy server CLI. You need both — pip runs the proxy, npm lets your JS code talk to it.

03
Add Headroom Marketplace to Claude settings.json
This registers the Headroom MCP marketplace source so Claude Code can discover headroom tools. Edit the file at C:\Users\akhileswar.konikinen\.claude\settings.json.
json ~\.claude\settings.json 
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          { "type": "command", "command": "rtk hook claude" }
        ]
      }
    ]
  },
  "autoUpdatesChannel": "latest",
  "extraKnownMarketplaces": {
    "headroom-marketplace": {
      "source": {
        "source": "github",
        "repo": "chopratejas/headroom"
      }
    }
  }
}
Key name is case-sensitive

The key must be extraKnownMarketplaces (camelCase). An earlier typo used extraknownMarketplaces (lowercase 'k') which silently fails — Claude Code won't show the marketplace but won't throw an error either.

04
Configure VSCode MCP Server for Headroom
This registers Headroom as an MCP server in VSCode so Claude Code can call headroom tools (compress, retrieve, stats) during conversations. Edit or create the file at C:\Playwright\Playwright_MCP\.vscode\mcp.json.
json .vscode\mcp.json 
{
  "servers": {
    "playwright-test": {
      "type": "stdio",
      "command": "npx",
      "args": ["playwright", "run-test-mcp-server"]
    },
    "headroom": {
      "type": "stdio",
      "command": "headroom",
      "args": ["mcp", "serve"],
      "env": {
        "HEADROOM_PROXY_URL": "http://127.0.0.1:8787"
      }
    }
  },
  "inputs": []
}
The env variable is critical

The HEADROOM_PROXY_URL tells the MCP server where to find the running proxy. Without this, the MCP tools will connect but can't reach the proxy — resulting in silent failures or long hangs.

§ 04

Starting the Proxy (Every Session)

This step is required every time

The headroom proxy is not a background service — it must be started manually in a terminal each session before launching Claude Code. Forgetting this step is the #1 cause of Connection Refused errors.

Standard startup

Open a dedicated PowerShell window and leave it running in the background while you work.

powershell Terminal Window 1 — keep this open 
# Start headroom proxy on default port 8787
headroom proxy

# You should see output like:
# INFO:     Started server process [PID]
# INFO:     Uvicorn running on http://127.0.0.1:8787

Then launch Claude Code

Open a second terminal window and start Claude Code with the environment variable set:

powershell Terminal Window 2 — your working terminal 
# Set the env var so Claude Code routes through headroom
$env:ANTHROPIC_BASE_URL = "http://localhost:8787"

# Then launch Claude Code normally
claude

Alternative: wrap command (one-liner)

powershell Starts proxy and wraps claude in one step 
# This starts the proxy and launches claude through it
headroom wrap claude

# Or with arguments:
headroom wrap claude -- --model claude-sonnet-4-6
How to know it's working

In the proxy terminal window you'll see live log lines for each request: POST /v1/messages — 200 OK with token counts. If Claude Code is not routing through headroom, the proxy window stays silent.

§ 05

Verifying the Setup

Run these checks after installation to confirm everything is wired up correctly before trusting it in real work sessions.

powershell Verification checklist — run each 
# 1. headroom CLI is installed
headroom --version
# Expected: headroom, version 0.26.0

# 2. headroom is in your PATH
where headroom
# Expected: path ending in \Scripts\headroom.exe

# 3. npm package is installed in project
npm list headroom-ai
# Expected: headroom-ai@0.22.4 (or later)

# 4. Proxy health check (proxy must be running first)
curl http://localhost:8787/health
# Expected JSON: {"status":"healthy","version":"0.26.0",...}

# 5. Port is listening
netstat -ano | findstr :8787
# Expected: TCP 127.0.0.1:8787  LISTENING
MCP server verification in VSCode

In VSCode with Claude extension: open the MCP panel and look for "headroom" in the server list. Its status should show as Connected once the proxy is running. If it shows "Disconnected" or "Error", the proxy is not running or HEADROOM_PROXY_URL is wrong.

§ 06

Checking Token Savings

Headroom exposes a stats endpoint and MCP tools for checking how many tokens have been saved. Use these to confirm compression is actually happening.

powershell Stats endpoints — proxy must be running 
# Live stats from the proxy HTTP API
curl http://localhost:8787/stats

# Detailed metrics
curl http://localhost:8787/metrics

# Recent request log
curl http://localhost:8787/log

The stats response shows fields like tokens_before, tokens_after, and tokens_saved_total. If tokens_saved_total is 0 after several Claude interactions, Claude Code is not routing through the proxy — double-check the ANTHROPIC_BASE_URL environment variable.

powershell Check env var is set in current session 
# Confirm the env var is set in your Claude Code terminal
echo $env:ANTHROPIC_BASE_URL
# Should print: http://localhost:8787
# If blank — it's NOT set. Claude Code is going direct to Anthropic.
Environment variables are per-terminal-session

Setting $env:ANTHROPIC_BASE_URL in PowerShell only applies to that terminal window. If you open a new terminal or restart, you must set it again — or add it to your PowerShell profile to make it permanent.

To make it permanent: add $env:ANTHROPIC_BASE_URL = "http://localhost:8787" to your PowerShell profile at $PROFILE.

§ 07

Troubleshooting

Every error encountered during our real setup, what caused it, and exactly how to fix it.

ERROR API Error: Unable to connect to API (Connection Refused)
Root Cause

The headroom proxy is not running. This is the most common error. Claude Code is trying to reach http://localhost:8787 but nothing is listening on that port. This can also appear after a long wait (the proxy timed out or was closed).

fix
# Open a new terminal and start the proxy
headroom proxy

# Keep that terminal open, then relaunch Claude Code
# in a separate terminal with the env var set
$env:ANTHROPIC_BASE_URL = "http://localhost:8787"
claude
SLOW Response takes many hours / times out silently
Root Cause

Headroom was configured to compress a very large context file before sending it. The compression itself took extremely long on first run (sometimes hours on large inputs), after which the API call failed. This happened when context files were loaded that exceeded headroom's efficient operating range.

fix
# Run headroom in passthrough mode first (no compression)
# to confirm the proxy is working at all
headroom proxy --no-optimize

# If that works, compression is the bottleneck.
# Re-enable compression but limit it:
headroom proxy --mode cache

# Or start with a budget to limit processing:
headroom proxy --budget 0.50 --budget-period daily
Large context files

If your prompts reference large text files (like full test plans, log files, or source code), headroom's compression can take significant time on those files. Break large context files into smaller chunks, or exclude them from compression by using headroom's passthrough mode for specific sessions.

ERROR 'headroom' is not recognized as an internal or external command
Root Cause

The Python Scripts directory is not in your system PATH. pip installed headroom but Windows can't find the executable.

fix
# Find where pip installed headroom
pip show headroom-ai
# Look at "Location:" field, e.g.:
# Location: C:\Users\...\Python312\Lib\site-packages

# The binary is in the Scripts folder parallel to Lib:
# C:\Users\...\Python312\Scripts\headroom.exe

# Add that Scripts path to System PATH:
# Settings > System > Advanced > Environment Variables
# Edit PATH > Add the Scripts folder path

# Verify after opening a NEW terminal:
headroom --version
WARN Headroom MCP server shows "Disconnected" in VSCode
Root Cause

The MCP server (headroom mcp serve) started successfully but can't reach the proxy because HEADROOM_PROXY_URL isn't set, or the proxy on 8787 isn't running.

fix
# Verify .vscode/mcp.json has the env section:
# "headroom": {
#   "type": "stdio",
#   "command": "headroom",
#   "args": ["mcp", "serve"],
#   "env": { "HEADROOM_PROXY_URL": "http://127.0.0.1:8787" }
# }

# Then make sure proxy is running:
headroom proxy

# Reload VSCode window to force MCP reconnect:
# Ctrl+Shift+P > Developer: Reload Window
WARN Tokens not being saved — stats show 0 compression
Root Cause

Claude Code is bypassing the proxy and connecting directly to Anthropic. The ANTHROPIC_BASE_URL environment variable is not set in the terminal where Claude Code is running.

fix
# Check if the variable is set in your current terminal:
echo $env:ANTHROPIC_BASE_URL

# If blank, set it:
$env:ANTHROPIC_BASE_URL = "http://localhost:8787"
claude

# To make it permanent (add to PowerShell profile):
notepad $PROFILE
# Add this line:
# $env:ANTHROPIC_BASE_URL = "http://localhost:8787"
The proxy must be running first

If you set ANTHROPIC_BASE_URL permanently in your profile but forget to start the proxy, every Claude Code launch will fail with Connection Refused. The recommended workflow: start proxy, then claude — in that order, every session.

ERROR Port 8787 already in use / EADDRINUSE
Root Cause

A previous headroom proxy instance is still running (possibly crashed but still holding the port), or another service is using port 8787.

fix
# Find what's using port 8787
netstat -ano | findstr :8787
# Note the PID in the last column

# Kill it (replace 1234 with the actual PID)
taskkill /PID 1234 /F

# Or use a different port:
headroom proxy --port 8788
# Then update ANTHROPIC_BASE_URL and mcp.json to match
