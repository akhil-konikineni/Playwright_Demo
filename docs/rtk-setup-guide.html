RTK — Rust Token Killer
Setup & Reference Guide

A complete guide to installing and configuring RTK as a transparent token-optimization layer for every shell command Claude Code runs — based on real usage that saved 89.9% of command output tokens.

rtk v0.42.4 Windows 11 Claude Code CLI 89.9% savings achieved Hook-based · zero overhead
§ 01

What RTK Does

RTK (Rust Token Killer) is a transparent CLI proxy. When Claude Code runs a shell command, RTK intercepts the output and strips all the noise — progress bars, padding, boilerplate headers, verbose paths — before that output enters Claude's context window.

The key word is transparent: Claude runs git status and gets back a filtered result. It doesn't need to know RTK exists, and you don't need to change any prompt or workflow. The savings happen automatically via a hook.

RTK vs Headroom — different jobs

RTK optimizes shell command output (the text that comes back from terminal commands). Headroom optimizes the conversation context sent to the LLM API. They work at different layers and are used together — RTK is not a replacement for Headroom.

§ 02

How It Works

RTK works through Claude Code's PreToolUse hook. When Claude is about to run a Bash command, the hook intercepts it and prepends rtk. RTK then runs the command, captures the output, and applies a specialized filter for that tool type before returning it.

The hook is configured once in ~/.claude/settings.json and applies globally to every project — you never touch it again.

how the hook works
# Claude wants to run:
git log --oneline -20

# Hook intercepts and rewrites to:
rtk git log --oneline -20

# RTK runs the command, strips noise, returns compact output
# Claude sees ~80% fewer tokens for the same information
Zero cognitive overhead

Once the hook is installed, there is nothing else to do. RTK works silently on every command. You do not need to prefix commands manually, change any prompts, or adjust any workflow. The only exception is when you want to run RTK meta-commands directly (rtk gain, rtk discover).

§ 03

Installation Steps

Three steps. Step 2 (the hook) is the critical one — without it, RTK is installed but does nothing for Claude Code.

01
Install the RTK binary
RTK is a Rust binary — no Python, no Node. Install from GitHub releases or via the install script. On this machine it is installed at C:\Users\akhileswar.konikinen\AppData\Local\Programs\rtk\rtk.exe.
powershellInstall RTK
# Option A — winget (recommended on Windows)
winget install rtk-ai.rtk

# Option B — download from GitHub releases
# https://github.com/rtk-ai/rtk/releases
# Download rtk-windows-x86_64.exe → rename to rtk.exe
# Add the containing folder to your PATH

# Verify install:
rtk --version
# Expected: rtk 0.42.4

# Confirm binary location:
where rtk
# Expected path ending in \rtk.exe
Name collision — important check

There is a different Rust package also called rtk (reachingforthejack/rtk — Rust Type Kit). If rtk gain gives an error or unrecognised command, you have the wrong binary. Run rtk --version — it should print rtk X.Y.Z not anything about types. Uninstall the wrong one first.

02
Add the Claude Code hook (critical step)
This is the step that actually activates RTK for Claude Code. Without the hook, RTK is installed but never called. Edit C:\Users\akhileswar.konikinen\.claude\settings.json to add the PreToolUse hook.
json~\.claude\settings.json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",
            "command": "rtk hook claude"
          }
        ]
      }
    ]
  },
  "autoUpdatesChannel": "latest"
}
Other config in settings.json

Your settings.json also contains extraKnownMarketplaces for Headroom. Keep all existing content — just add the hooks block. Replacing the whole file loses your Headroom marketplace config.

How the hook command works

rtk hook claude is RTK's Claude Code integration mode. It reads the incoming Bash command from Claude's tool-use payload, rewrites it to the appropriate rtk <command> form, and returns the filtered output. RTK knows which filter to apply based on the command name.

03
Verify the installation is working
Restart Claude Code after editing settings.json. Run these verification checks — if RTK is working, you should see savings appear immediately.
powershellRun in terminal (not inside Claude Code)
# 1. RTK binary is reachable
rtk --version
# Expected: rtk 0.42.4

# 2. RTK knows about savings (shows empty if first run)
rtk gain

# 3. Verify hook integrity
rtk verify

# 4. Config file location
rtk config
# Shows: C:\Users\...\AppData\Roaming\rtk\config.toml

# 5. After a Claude Code session — check savings appeared:
rtk gain --history
If rtk gain shows 0 after a full session

The hook is not active. Causes: (1) settings.json was not saved correctly — open it and confirm the hooks block is present. (2) Claude Code was not restarted after editing — close and reopen. (3) The hook command has a typo — it must be exactly rtk hook claude.

§ 04

Key Commands

These are the RTK meta-commands you run yourself (not through Claude). All other RTK commands run automatically via the hook.

analytics commands — run these yourself
rtk gain Overall token savings summary — total tokens, saved count, percentage, top commands by impact
rtk gain --history Per-command breakdown — every individual command with its savings count and average percentage
rtk session Session-by-session view — shows adoption rate across your last 10 Claude Code sessions
rtk discover Scans Claude Code history for commands that were NOT routed through RTK — finds missed savings
rtk verify Checks hook integrity and runs built-in filter inline tests — use after any settings change
rtk config Shows current configuration and config file path
rtk telemetry Manage anonymous telemetry consent — currently disabled on this machine
debug commands — for when something seems wrong
rtk proxy <cmd> Run a command through RTK tracking but without filtering — useful to confirm RTK is seeing commands
rtk run <cmd> Execute via sh -c completely raw — no filtering, no tracking. Pure passthrough for debugging
rtk err <cmd> Run command and show only errors and warnings — strips all successful output
rtk learn Learn CLI corrections from Claude Code error history — helps RTK improve its filters
§ 05

Built-in Filters

RTK has purpose-built filters for each tool. When Claude runs one of these commands, the filter for that tool is applied automatically. Highest-impact filters for this project:

filters used in this project
rtk read <file> Biggest savings in our project — 45.6K tokens saved. Strips file padding, comments, and repetitive lines. Our #1 most-called filter.
rtk ls -la <path> Directory listings with noise removed — permissions columns, owner/group, sizing details. Keeps filenames and modification dates.
rtk git <cmd> Git output with compact formatting — diff headers, status abbreviations, short log format. Strips ASCII decoration.
rtk npm <cmd> npm install/run output stripped of progress bars, timing lines, and boilerplate. Keeps errors and key outcomes.
rtk playwright <cmd> Playwright test output showing only failures — skips passing test lines, strips runner decoration.
rtk curl <url> Auto-detects JSON responses and applies schema-based compression — shows structure, not full payload.
other available filters (full list)
rtk tree <path>Directory tree with token-optimized output
rtk diff <args>Ultra-condensed diff — only changed lines, no context bloat
rtk grep <args>Compact grep — strips whitespace, truncates, groups by file
rtk json <file>JSON with compact values, or keys-only with --keys-only
rtk log <cmd>Filter and deduplicate log output — removes repeated lines
rtk test <cmd>Run tests and show only failures — pass/skip lines suppressed
rtk depsSummarize project dependencies from package.json
rtk envShow environment variables with sensitive values masked
rtk tsc <args>TypeScript compiler with grouped error output
rtk docker <cmd>Docker commands with compact output
rtk read is the highest-impact filter

In our project, rtk read saved 45.6K of the 49.8K total tokens saved — that's 91% of all RTK savings from a single filter. Any time Claude reads a file, RTK is working hardest.

Checking Savings

Run these at the start of a session to confirm RTK is active, or after a session to review how much was saved.

rtk gain

# RTK Token Savings (Global Scope)
# Total commands:    54
# Tokens saved:      49.8K (89.9%)
# Efficiency meter: ██████████████████████░░ 89.9%

# Session-by-session breakdown
rtk session

# Sample output:
# Session    Date     Cmds  RTK  Adoption
# f13806de   Today      14    6      43%
# 86a4bb41   Today      14   12      86%

# Find commands that MISSED RTK filtering
rtk discover
Low adoption rate in rtk session

If rtk session shows adoption below 50%, RTK is filtering some commands but not all — either the hook isn't matching all Bash calls, or some sessions were started without the hook active. Run rtk discover to identify which command types are being missed.

§ 07

Troubleshooting

ERROR 'rtk' is not recognized as a command
Root Cause

RTK binary exists but is not in your PATH, or the install directory was not added.

fix
# Find where rtk was installed
where rtk
# If this also fails, rtk is not installed

# On this machine, the binary is at:
# C:\Users\akhileswar.konikinen\AppData\Local\Programs\rtk\rtk.exe
# Add that directory to System PATH
# Settings → System → Advanced → Environment Variables → PATH
WARN rtk gain shows 0 savings after a full Claude session
Root Cause

The PreToolUse hook is not active. RTK is installed but Claude Code is running Bash commands without going through RTK.

fix
# 1. Check settings.json has the hooks block
notepad %USERPROFILE%\.claude\settings.json
# Must contain "hooks" → "PreToolUse" → "rtk hook claude"

# 2. Restart Claude Code — hooks are read at startup

# 3. Verify hook integrity
rtk verify

# 4. If still 0, check for typo in hook command:
# Correct:   "command": "rtk hook claude"
# Wrong:     "command": "rtk hook" (missing "claude")
# Wrong:     "command": "rtk" (missing "hook claude")
ERROR rtk gain fails or returns wrong output (wrong rtk installed)
Root Cause

The wrong rtk binary is installed — reachingforthejack/rtk (Rust Type Kit) rather than rtk-ai/rtk. Both have the same binary name.

fix
# Identify which rtk you have:
rtk --version
# Should print:  rtk X.Y.Z  (rtk-ai version)
# Wrong version: any output about "Rust Type Kit" or types

# If wrong: uninstall it first, then reinstall rtk-ai/rtk
# Check installed programs and remove the conflicting one
# Then reinstall from: https://github.com/rtk-ai/rtk/releases
WARN RTK session shows low adoption (below 50%)
Root Cause

Some Bash commands are not being intercepted by the hook. This can happen if commands are run in subshells, or if certain Claude tool types bypass Bash.

fix
# Find exactly which commands are being missed
rtk discover

# Review session-level adoption
rtk session

# For commands RTK doesn't have a filter for,
# use rtk proxy to at least track them:
rtk proxy <your-command>
