## RULES

### Format
- Summary = Description always; BDD pattern only; ≤255 chars
- IssueId, Project, Issue_Type, Summary, Description, Test Repository, Test Status, labels → first row per TC only
- Test Data → login row only; all others BLANK
- All 5 sections, no skips; IssueId continues sequentially across all 5 sections
- Use actual field names from Part 8 only — no placeholders like Field1, FilterA, Dropdown1
- No duplicate TCs | Test Status=TODO | regression-Yes always | sanity-yes=smoke only

### Out of Scope — NEVER generate
SQL injection, XSS, CSRF, security/penetration, API load/stress/performance, network failure, browser compatibility

### Consolidation — UI + API + DB in one flow per TC
- **Create/Update success:** fill → submit → success banner → list verification → API response → DB verify
- **Filter/search:** apply → list matches → API GET → DB verify
- **Dropdown options:** open → UI options → API → DB active records
- **Column/table:** headers visible → API GET → DB records
- **Exception:** UI-structural checks (button visibility, labels, colors, asterisks, tooltips) are UI-only TCs — no API/DB steps needed
